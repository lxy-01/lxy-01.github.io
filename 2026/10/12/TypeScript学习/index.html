TypeScript学习

TypeScript 简介

  • 定义：由微软开发、基于 JavaScript 的扩展语言。

  • 本质：TypeScript 是 JavaScript 的超集——包含 JS 的所有内容。

  • 增量能力：在 JS 之上增加 静态类型检查、接口、泛型 等现代开发特性，更适合大型项目开发。

  • 运行方式：浏览器不能直接运行 TS，必须编译为 JavaScript 后再交给浏览器/JS 运行环境执行。

  • 一句话记忆：TS = JS + 类型系统（静态类型检查）。

为何需要 TypeScript

JS 的四大困扰

  1. 不清楚的数据类型
  2. 有漏洞的逻辑
  3. 访问不存在的属性
  4. 低级的拼写错误

静态类型检查

  • 含义：在代码运行前进行检查，发现错误或不合理之处，降低运行时异常概率。

  • 核心价值：把「运行时的错误」前置到「编译时/写代码时」。

  • 代价：TS 代码量 > JS；但结构更清晰，后期维护 TS 胜出。

类型声明

语法：在变量或函数形参后用 : 声明类型。

字面量类型：: 后也可写字面量类型（实际开发中用得不多）。

  • 用途：把「约定」写成代码，编译器替你检查赋值、传参、返回值。
  • 类型声明是开发期约束，编译后类型信息全部擦除，不影响运行结果。

类型推断

  • 含义：TS 会根据代码自动推导变量类型，无需显式声明。

  • JS 八大内置类型（TS 可直接推断）：string、number、boolean、null、undefined、bigint、symbol、object。

    • 其中 object 涵盖 Array、Function、Date、Error 等。

  • 重要：类型推断不是万能的，面对复杂类型时容易推断出错（如 any 蔓延）。

  • 建议：复杂场景下尽量显式编写类型声明。

类型总览

TS 的数据类型 = JS 全部类型 + 6 个新类型 + 2 种自定义类型。

分类 内容
① JS 已有类型 string number boolean null undefined bigint symbol object
② 六个新类型 any unknown never void tuple enum
③ 两种自定义方式 type interface

原始类型 VS 包装对象 重点易错

  • 原始类型：number string boolean，简单数据类型，占用空间少、速度快。
  • 包装对象：Number String Boolean 对象，复杂类型，占空间多，日常开发很少手动创建。
  • 自动装箱：JS 在必要时自动把原始类型包装成对象，以便调用方法/访问属性。
  • 结论：TS 中声明类型统一用小写 number / string / boolean，不要用大写包装对象。

  • 含义：任何值都不是——undefined、null、''、0 都不行。
  • 几乎不直接用它限制变量（无意义）：
  • 真实用途：TS 主动推断 + 限制函数返回值。
  • 记忆：never = 不可能存在的值；常出现在「穷尽分支」和「永不返回的函数」。

void

  • 含义：空——函数不返回任何值，调用者也不应依赖其返回值做任何操作。
  • 语法细节：没写 return 时，函数隐式返回 undefined；void 是可以接受 undefined 的。
  • void 与 undefined 的区别（返回值限制时）：
  • 理解：void 是广泛的概念（表达”空”），undefined 是这种”空”的具体实现；void 包含 undefined，但语义上更强调意图上的约定。
  • 总结：
    1. 语法上：返回类型为 void 的函数可以返回 undefined（显式/隐式都行）。
    2. 语义上：调用者不应关心、也不应依赖其返回值。

  • object（小写）：所有非原始类型——对象、函数、数组等。

  • Object（大写）：所有可以调用 Object 方法的类型。

    简单记忆：除了 undefined 和 null 的任何值。

  • 两者范围都太大，实际开发使用频率极低。

对象 / 函数 / 数组 的类型声明

  • 两个 => 的区别（易混）：
    • TS 类型中的 =>：表示函数类型（描述参数/返回类型）。
    • JS 代码中的 =>：是箭头函数的语法（具体实现）。
  • 函数类型也可用接口或自定义类型来声明。

tuple（元组）

  • 含义：特殊的数组类型，元素数量固定、每个元素类型已知且可不同，用于精确描述一组值。
  • 语法：? 表示可选元素，...T[] 表示剩余元素。
  • 本质是数组，长度与顺序是约束的一部分，不能随意增删元素。

enum（枚举）

  • 含义：定义一组命名常量，增强可读性、便于维护。
  • 典型场景：up/down/left/right 这类连续且相关的一组值；避免调用方传错字符串且无提示。

数字枚举

数字枚举⼀种最常见的枚举类型，其成员的值会自动递增，且数字枚举还具备反向映射的特点

  • 反向映射**：数字枚举可通过值反查成员名（Direction[0] → 'Up'）。

字符串枚举

枚举成员的值是字符串

  • 字符串枚举没有反向映射，成员值必须显式赋值（或全部同类型）。

常量枚举（const enum）

常量枚举是⼀种特殊枚举类型，它使⽤ const 关键字定义，在编译时会被

内联，避免⽣成⼀些额外的代码。

  • 编译时内联：编译时把枚举成员引用替换为实际值，不生成额外枚举对象。
  • 好处：减小生成的 JS 体积、提升运行时性能。

type（类型别名）

  • 含义：为任意类型创建别名，让代码更简洁、可读性更强，便于类型复用与扩展。

联合类型（Union）

  • 含义：一个值可以是几种不同类型之一，用 | 连接。

交叉类型（Intersection）

  • 含义：把多个类型合并为一个，合并后拥有所有被合并类型的成员，通常用于对象类型。
  • 记忆：联合 | 是”或”（多选一），交叉 & 是”且”（全部都要）。

复习：类（class）相关知识

  • 子类构造器中必须先 super() 才能用 this。
  • 若子类不需要额外属性，构造器可以省略（自动继承父类构造器）。
  • override` 明确标记「重写父类方法」，便于发现拼写/签名错误。

抽象类（abstract class）

  • 概述：一种无法被实例化的类，专门用于定义类的结构与行为；类中可写抽象方法，也可写具体实现。
  • 作用：为派生类提供基础结构，并要求派生类必须实现其中的抽象方法。
  • 简记：抽象类不能实例化；意义在于被继承；里面可以有普通方法，也可以有抽象方法。
  • 何时使用抽象类：
    1. 定义通用接口：为一组相关类定义通用行为（方法/属性）。
    2. 提供基础实现：在抽象类中写好通用实现，供派生类继承。
    3. 确保关键实现：强制派生类实现某些关键行为。
    4. 共享代码和逻辑：多个类共享部分代码时，避免重复。

interface（接口）

  • 含义：一种定义结构的方式，核心作用是为类、对象、函数规定一种契约，确保代码一致性与类型安全。
  • 只能定义格式，不能包含任何实现代码。
  • 何时使用接口：
    1. 定义对象格式：描述数据模型、API 响应格式、配置对象等（最常用）。
    2. 类的契约：规定一个类需要实现哪些属性和方法。
    3. 扩展已有接口：常用于扩展第三方库的类型（大型项目常见）。

相似概念的区别

interface VS type

interface type
定义对象结构 ✅ ✅（两者可互换）
继承 ✅ extends ❌ 不支持继承（可用交叉类型 & 替代）
自动合并 ✅ 同名接口自动合并 ❌ 不支持自动合并
别名/联合/交叉 ❌ ✅ 可定义类型别名、联合类型、交叉类型
  • 结论：interface 专注「对象/类的结构」，支持继承与合并；type 更灵活，能表达联合、交叉与别名。

泛型

  • 含义：在定义函数、类或接口时，用类型参数表示未指定的类型；这些参数在具体使用时才被指定为具体类型。
  • 价值：让同一段代码适用于多种类型，同时仍然保持类型安全。
  • <T> 中的 T 只是名字，叫什么都行（约定俗成用 T、U、K、V）。

泛型约束（extends）

  • 含义：用 extends 限制类型参数必须满足的条件。
  • 注意：泛型约束里的 extends 表示「必须满足某结构」，与类继承的 extends 不是一回事。

类型声明文件

  • 定义：扩展名为 .d.ts 的特殊文件。
  • 作用：为现有的 JavaScript 代码提供类型信息，让 TS 在使用这些 JS 库/模块时能进行类型检查和提示。
  • 场景：引入无类型的第三方 JS 库、为老项目补充类型。
  • 记忆：.d.ts = 只写”长什么样”，不写”怎么做”。
